# 0.3.0 release notes

Version 0.3.0 adds scrolling menus, broader Windows display support and more
reliable installation and configuration on both platforms.

## Changes since 0.2.0

- **Menus fit your terminal.** Long computer, monitor and device lists scroll
  with the selection. Page Up/Down, Home/End, wrapped descriptions and resizing
  work on both platforms, with numbered input for very small windows.
- **More Windows display support.** Standard-DDC monitors can use the explicit
  `dxva2` transport on other GPUs at the local console. NVIDIA remains required
  for the supported LG manufacturer method and for switching before login.
- **Clearer device selection and status.** Setup names devices and can
  distinguish USB devices of the same model when their connection information
  permits it. `status` reports how the saved configuration resolves now, the
  configured input map, watcher state and installed build. Trigger edits need
  `restart`; status does not read a running watcher's loaded configuration.
- **Safer configuration and checks.** Cancel discards submenu edits, Save
  preserves unknown keys and disconnected monitors, and ambiguous display or
  trigger identities are refused. Trigger checks require current monitor
  checks and preserve the watcher's prior state where they can pause it.
- **More reliable installation and startup.** Installer failures report what
  remains and avoid claiming success. Upgrades preserve configuration and
  unrelated PATH entries; “No” autostart runs only for the current session.
- **Windows boot security and account handling.** Boot tasks start an ordinary
  user watcher through a restricted bootstrap. Standard-user registration,
  cancellation, dependency loading and cleanup of owned processes have native
  regression coverage. Paths with spaces, apostrophes and Unicode are covered.

## Install or upgrade

Follow the [installation guide](../../README.md#install) for prerequisites and
setup. Select the `v0.3.0` tag or its source archive before
running the installer. From a clean existing checkout:

```sh
git fetch origin --tags
git checkout v0.3.0
```

Then run `./install.sh` from `macos`, or the documented PowerShell installer
command from `windows`. Run as the intended user, unelevated. Back up your
configuration privately before upgrading; the installer retains it. Open a
new terminal and run `trigger-kvm status` to check the installed version.
Updating a checkout alone does not update the installed program or boot task.

Existing 0.2.0 configurations are retained; there is no required configuration
file conversion. On Windows, boot registration by a different administrator
also requests the intended user's **account password**, not a Windows Hello
PIN. Choose login if that password is unavailable or local policy prevents
boot registration. See the [Windows installation guide](../../windows/README.md#install).

Maintainers with a checkout from before the privacy rewrite must follow the
[fresh-clone migration](../privacy.md#refreshing-the-windows-checkout) instead
of merging or pushing the old history.

## Compatibility and validation

The shared contract is specification revision **16**. macOS requires Apple
Silicon and `m1ddc`; Windows requires 64-bit Windows 10 or 11, Windows PowerShell
5.1 and Windows Script Host with VBScript enabled.

Physical evidence covers the reference Apple Silicon Mac and Windows 11 / RTX
4090 desk with an LG 45GX950A and ASUS PG42UQ. The ASUS also has a visually
confirmed round trip through the shipped `dxva2` path at the Windows local
console. Installation, startup and physical observations are recorded in
[`docs/measurements.md`](../measurements.md), along with native validation on
both platforms. Automated tests do not establish compatibility with other
monitors, GPUs, adapters or Windows versions.

## Known limitations

- `dxva2` requires a local console session; it cannot switch before login or
  over Remote Desktop. The LG manufacturer method requires NVIDIA on Windows.
- Windows restricted session-0 physical checks ran after local sign-in. They
  do not establish a detector-triggered or pre-login physical write for that
  exact secured installation. Earlier observations remain separately dated.
- Monitors reporting the same identity cannot be managed together. Trigger
  ambiguity is a refusal, not a reason to guess which device arrived.
- Wake is not a trigger. Disable monitor automatic input selection; otherwise
  a monitor can drift to another computer until the next USB-switch event.
- A switch can briefly blank the display while the video link reconnects.
  Verify input changes by eye. Do not experiment with manufacturer commands.
- Intel Macs and Linux are not supported.

The [safety notes](../../README.md#safety) apply to both installation checks and
manual switching. When sharing diagnostics, remove personal identifiers as
described in [Contributing](../../CONTRIBUTING.md#reporting-a-bug).
